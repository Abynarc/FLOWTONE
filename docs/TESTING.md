# Проверки FLOWTONE

Тесты используют общий код настоящего плагина. Аудиоданные генерируются синтетически; пользовательские записи не требуются.

Windows: `./packaging/build_windows.ps1 -WithChecks`.
macOS: `cmake -S . -B build-ci -DCMAKE_BUILD_TYPE=Release -DFLOWTONE_BUILD_VERIFICATION=ON`, затем `cmake --build build-ci --target FLOWTONE_verify --parallel 4`.

Команды запуска и подготовка тестовых данных находятся в [.github/workflows/macos.yml](../.github/workflows/macos.yml) и [.github/workflows/windows.yml](../.github/workflows/windows.yml). Вывод проверок и код возврата сохраняются в CI.

Автоматические проверки покрывают DSP, сохранение состояния и основные сценарии работы. Прослушивание, PDC/bounce и настоящий перенос регионов в Logic/FL Studio проверяются отдельно в соответствующем хосте.

## Темп в версии 0.3.3

Новый тест `.github/checks/tempo_checks.py` проверяет 42 синтетических ритмических записи в файловом и онлайн-анализе: 32 стресс-ритма и 10 дополнительных аранжировок с дробными BPM, пропусками ударов и джиттером. Диапазон 45–240 BPM, частоты дискретизации 16/44,1/48/96 кГц.

Основной, половинный и двойной темп считаются допустимыми; допуск сравнения — ±1%. Трети и отношения 2/3 не засчитываются. В прежних проверках точности сохранён допуск 0,25 BPM после приведения к разрешённому уровню.

Дополнительно проверяются тишина, шум, стационарные тоны, смена темпа, длинное тихое окончание, сброс, сохранение новых данных, старые состояния проектов и некорректный кэш. Результаты сохраняются в `acceptance.json` внутри диагностических артефактов GitHub Actions.

Локальный прогон macOS: 42/42 допустимых BPM в обоих режимах, 4/4 неритмичных сигналов без ложного BPM. На тех же 42 записях файловый анализ 0.3.2 дал 35/42, Essentia Multifeature — 40/42. Это сравнение синтетических записей, а не оценка точности на произвольной музыке. Старые 31 результат тональности совпали с прежней версией.

Многопризнаковый движок реализован на C++; Essentia использовалась только для независимого сравнения и не включена в плагин. Источник подхода: [BeatTrackerMultiFeature](https://essentia.upf.edu/reference/std_BeatTrackerMultiFeature.html).
